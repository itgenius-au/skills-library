# Step 3, snapshot rules 5 to 7: redaction and privacy

Placeholders (`<REVIEW_SKILLS>`, `<SCRATCH>`, `<PROJECT_DIR>`, `<snapshot>`, `<RANGE>`) are defined in SKILL.md under "Invocation form".

5. **A live key in any branch's history reaches the legs' providers.** A snapshot shares the object store, so a leg can `git show <other branch>:<file>` and send that text to Codex, Gemini, z.ai or Anthropic. When any reachable history holds a live credential: copy each key-bearing file with the key replaced into the leg's snapshot (for example `review-context/<file>.REDACTED`), name those blobs in the prompt as forbidden, build the GLM packet only from the redacted copies, and after the panel grep every leg output for the key's first characters (0 hits required) before you read a verdict.
6. **Personal and customer data stays out of non-Anthropic legs.** For work that involves customer or personal data, build a list of the names and emails that appear in the plan, the diff and the script comments, plus any bank details (account numbers, IBANs, last-4 digits, including other payees' values read from live lists while building fixtures), and redact them from the WHOLE packet: docstrings, runbooks and test fixtures, not only the data blocks. Then grep the finished packet (and any build-review prompt) for each name and value, and do not send it until there are 0 hits. A name often survives in a script's docstring or a runbook after the data blocks are already clean. Use obviously fake example values in fixtures (for example `000-000` and `...1234`). A branch or sort code is public; the account number and its last 4 digits are the parts that must be fake.
   **When a name is in the subject's own diff or files, give Codex and Gemini a redacted export, not a git snapshot.** Redacting a snapshot's files is not enough: a repo-capable leg runs `git diff` or `git show`, and git prints the committed text, so a name the diff adds (a test fixture, say) still reaches that leg's provider. Instead, write the names one per line to `<SCRATCH>/names.txt` and run, per leg:
   `python3 <REVIEW_SKILLS>/review-swarm/scripts/redacted_export.py --repo <repo> --base <merge-base> --head <checkpoint-sha> --names <SCRATCH>/names.txt --out <SCRATCH>/redacted-<slug>-<leg>`
   It writes a copy with no `.git` and the diff at `<out>/.review-swarm/diff.txt`, both redacted, and exits 1 if a name survives anywhere (a name in a file path needs a rename by hand). It needs Python 3.12 or newer. Run Codex with `--dir <out>` and say in its prompt that the diff is in `.review-swarm/diff.txt` and the folder has no git; run Gemini with `--dir <out> --stdin-file <out>/.review-swarm/diff.txt`; build the GLM packet from the export. Fable keeps its git snapshot (Anthropic). Leave Codex and Gemini off the `snapshots.sh` and `postpanel.sh` leg lists (the exports are not worktrees), and delete the exports after the panel. Then grep every leg output for each name, with a positive control on an unredacted copy, and report any hit.
7. **`doc` mode on a personal or financial document** (a plan, decision, or legal or tax document with IBANs, national or tax ids, VAT ids, emails, Drive or Gmail ids): `redacted_export.py` needs a git repo, so use `redact_doc.py` instead, then inline the copy, not the original, to every leg.
   `python3 <REVIEW_SKILLS>/review-swarm/scripts/redact_doc.py <doc> --out <SCRATCH>/subject-<slug> [--extra <literal> ...]`
   The default patterns are generic Spanish and EU formats plus emails and Google Drive and Gmail ids (`redact_doc_patterns.txt`); pass a person-specific value (a name, a registry code) with `--extra`, or your own file with `--patterns` (it replaces the defaults, so use it for another locale's formats). It exits 1 and removes the copy if any pattern or `--extra` still matches the copy; it cannot see a value no pattern covers. So its count table is only half the positive control: each value type in the document must show a count above 0 in the original and 0 in the copy, AND you read the copy once for any personal value still in plain text (a name, an address, a format the patterns miss). Add each one as an `--extra` and run again. After the panel, run `redact_doc.py <doc> --check <SCRATCH>/<leg-outputs> [--extra ...]` (same `--extra` and `--patterns`) before you read a verdict: it searches every leg output for the original raw values, prints the file and placeholder of each hit (never the value), and exits 1 on any hit.
