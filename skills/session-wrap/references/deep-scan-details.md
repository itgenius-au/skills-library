# Step 4: reading the deep session scan

(`$SKILL_DIR` is this skill's base directory, printed when the skill loads. Invoke the scan through `bash` so a lost executable bit does not matter. It needs only `python3`.) The scan resolves THIS session's transcript, stitches its sibling windows on the same worktree, filters injected content (system reminders, task notifications, skill bodies, tool output, heartbeats), and prints a bounded digest: `EVIDENCE <file>:<line> | role | directive | quote` lines, `INFERRED ...` lines, `SPAN <file>` lines for the transcripts it read, and a final `DEEP_CANDIDATES=0|1`. It degrades cleanly (one `NOTE` plus `DEEP_CANDIDATES=0`) and never breaks a wrap. It never loads a whole transcript into your context. It looks for:

- **Explicit directives** (typed by the user, fire at n=1): "from now on", "going forward", "next time", "update the skill", "why isn't this a skill", "make this a hook", "always ...", "never ...", and scope rejections such as "I didn't ask for that".
- **Corrections and redos** (inferred, need n>=2): the user rewording the same instruction, "no, ...", "that's wrong", "are you sure".
- **Repeated tool errors** (inferred, need n>=2): the same failure twice or more. Pure harness noise (a worktree-isolation refusal, an expired MCP login prompt) is ignored.

It also reads the messages the user typed while a turn was running (stored as `queued_command` records, not as normal user turns): each counts as a typed user turn with its own line number, and only the user's own words are read, never the harness wrapper text around them. The scan reads every `<session id>.jsonl` across project folders (a session that resumed in another worktree has two). It lists them in one `NOTE` and removes records copied between them. A file whose records were all duplicates prints no `SPAN` of its own.

When `CLAUDE_CODE_SESSION_ID` is set, the scan finds `<session id>.jsonl` by searching every folder under the projects directory, and uses it as the seed transcript before any path-based guessing. A session that entered and exited worktrees keeps writing to its launch folder, so a path-based match alone can read an empty folder. If the variable is unset or no file matches, the scan prints one `NOTE` and falls back to path-based discovery. It never prints a `SPAN` line for a file that does not exist.

If it finds 0 evidence on a seed transcript over 200 KB with 5 or more typed user turns (a genuine user turn longer than an ack such as "go"), it prints `NOTE 0 directives matched <n> typed user turns; review the typed turns by hand (the transcript path is right)`, followed by up to 10 `WEAK <file>:<line> | <first 120 chars>` lines (typed turns over 60 characters) for the deep pass to read. Treat that note as "no pattern matched, read the typed turns", never as "nothing found". (The older `NOTE SCAN-SUSPECT: ... check the transcript path` wording remains only for a transcript not resolved by session id: there, check the path.) With fewer typed turns it prints `NOTE 0 evidence is expected: only <n> typed user turns ...` instead: an autonomous session where the user typed only "go" has nothing to find. This note explains the scan only. It is never a reason to skip the deep pass (see "Deep pass" in SKILL.md).

Outside a git work tree, the scan still runs when `CLAUDE_CODE_SESSION_ID` names a transcript: it scans only that transcript and prints `NOTE not in a git work tree: scanning only this session's transcript`. With no id, it prints `NOTE not in a git work tree; deep scan skipped`.

The repeated-tool-error signal ignores worktree-isolation guard refusals ("this session is isolated in the worktree ...") and MCP re-auth errors ("needs you to sign in again"). They are harness noise, not lessons.

The session-id transcript counts in full, whatever working folder each record carries, so a session that worked inside worktrees still has its evidence when it wraps from elsewhere. From a main checkout (not a linked worktree) with the session id resolved, the scan reads ONLY that transcript and prints `NOTE main checkout: scanning only this session's transcript`: the folder path appears in nearly every session that ever ran there, so it identifies nothing.

If `python3` or the transcript folder is missing, the scan skips with a `NOTE`. Then fall back to reading the transcript yourself in slices (`find "$HOME/.claude/projects" -name "${CLAUDE_CODE_SESSION_ID}.jsonl"`), or hand it to a subagent. Never load the whole file into your own context, and only the user's typed turns carry lessons: skip injected content such as system reminders, tool output, and skill bodies.
